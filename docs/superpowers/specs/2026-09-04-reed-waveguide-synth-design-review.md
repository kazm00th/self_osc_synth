## 重 — 実装前に決めないと後戻り

### R1. パネル4のデータ源が矛盾（§7、設計書 :245）

「マウスピース圧の波形」を `AnalyserNode` で取る、と書いてある。取れない。
`AnalyserNode` は Web Audio ノードの出力にしか繋がらず、`p̃` は worklet 内部の量。
worklet の出力は §4.5 のベル透過音であって `p̃` ではない。

**修正案**: worklet を2出力にする。

- `out[0]` = 放射音 → `destination`
- `out[1]` = `p̃` → `AnalyserNode` のみ。`destination` には繋がない

### R2. 裏返りインジケータが3次を基音と誤認する（§6、設計書 :233-236）

「スペクトルのピーク」から f0 を推定する方式。以下の理由で成立しない。

- クラリネット波形は3次成分が基音より強いことが常
- 出力には `(1+R)` のハイパスが掛かり、基音がさらに減衰する（R4 参照）
- → 第1レジスタでも「比 ≈ 3」と出続ける

分解能も不足。fftSize 2048 @48 kHz で bin = 23.4 Hz。
L=1.2 m の f0 = 71.5 Hz は3 bin しかない。

**修正案**: ピーク検出は不可。自己相関、または倍音列マッチング
（f0 候補に対し f, 3f, 5f のエネルギー総和を評価）を使う。

### R3. リード IIR の形式が §7 の `x'` 可視化と両立しない（§4.1、設計書 :116-120）

「双一次変換による2極 IIR」= 直接形。直接形の内部状態は `x` と `x'` ではない。
一方 §7 パネル1 は `(x, x')` の相図を要求し、snapshot にも `xd` フィールドがある。
差分 `(xₙ − xₙ₋₁)·fs_internal` での代用は可能だが、設計書に記述がない。

さらに問題: 開放/接触の係数切替は `x = 0` 交差ごと（≒毎周期2回、音声レート）に起きる。
直接形は係数を切替えると内部状態の物理的意味が変わり、過渡が乗る。不安定化もありうる。

**修正案**: `(x, x')` を状態変数に持つ台形則の状態空間形にする。
係数切替が連続になり、`x'` が状態から直接取れる。両方が同時に解決する。

### R4. 低域を三重に削っている（§4.5 / §4.4、設計書 :178-180）

`(1+R)` は DC で `R = −1` ゆえ利得 0、高域で 1。**すでに1次ハイパス**。
そこへ「+ 1次ハイパス（放射 ≈ dp/dt）」を掛け、さらに最終段に DC ブロッカ。計3段。

**修正案**: `(1+R)` が放射微分の役を果たしている。追加ハイパスは不要。
DC ブロッカのみ残す。

### R5. k-rate は「ジッパーノイズが出ない」の逆（§3、設計書 :60）

k-rate = 128サンプル毎の階段（2.67 ms @48 kHz）。それがジッパーノイズの発生源そのもの。
サンプル毎に滑らかなのは a-rate。

特に `tubeLength`: D が 2.67 ms 毎に飛ぶ → 遅延線の読み出しポインタが跳ぶ → クリック。
§4.5 は線形補間を「管長を連続的に動かす要件があるため」に選んでいるのに、
上流が階段では意味がない。

**修正案**: `gamma` と `tubeLength` は a-rate、またはブロック内で線形補間。
残りは k-rate で可。

### R6. γ の範囲と倍率が整合しない（§5 :199 / §6 :224-227）

`gamma` の範囲は 0 – 1.0。一方 γ 倍率は
ブレス(CC2) が「概ね 0..1.15」、モジュレーション(CC1) が「1.0..1.5」。
これをベロシティ由来のピーク値に掛ける仕様。

ピーク 0.8 × 1.5 = 1.2 → 1.0 でクランプ。
§6 の「意図的に12度へ追い込む」が天井で効かなくなる。

物理的には γ > 1 は静的閉鎖（吹圧のみでリードが閉じる）で発振しないため、
max = 1.0 という上限自体は妥当。**壊れているのは「ベロシティピーク × 倍率」の写像**。
倍率適用後にどう 1.0 以内へ収めるかが未定義。

### R7. ノートオン時の管長不連続が未定義（§6、設計書 :218）

`setValueAtTime` で L を瞬時に変える。遅延線の中身は前の音の波。
D が飛ぶと読み出し位置が跳んで不連続になる。`D ≥ 2` のクランプでは防げない。

**要決定**: D の変化レート制限（ポルタメント）か、ノートオン時に遅延線をクリアするか。
モノフォニック後着優先のレガート挙動も、この決定に依存する。

## 中

### R8. パネル3の 256点は「間引き」ではなく引き伸ばし（§7、設計書 :244）

`D = L·fs/c`。L = 0.15 – 1.2 m, c = 343 m/s, fs = 48 kHz →
**D = 21 – 168 サンプル**。256 より短い。

L = 0.15 m では管全体が 21 点しかなく、定在波の節・腹（1次 → 3次）は見えない。
2× なら 42 – 336 で改善するが、1× の短管は解決しない。

**修正案**: 可視化側で補間する旨を明記するか、点数を D に応じて可変にする。

### R9. snapshot 1024 サンプルでは低音の「直近2周期」が入らない（§7 :243, :253）

L = 1.2 m → f0 = 71.5 Hz → 1周期 671 サンプル → 2周期 1343 > 1024。
**L > 約 0.9 m で破綻する。**

併せて: 1024 サンプル @48 kHz = 21.3 ms、送出間隔は 33.3 ms（30 Hz）。
**36% は欠落した非連続サンプル**。相図には無害だが、波形パネルに使うなら明記が要る。

### R10. MIDI 下限の数値が誤り（§6、設計書 :219）

「L 0.15–1.2 m ≒ MIDI 35–74」とあるが、
L = 1.2 m → f = 343/(4×1.2) = 71.46 Hz → MIDI = 69 + 12·log2(71.46/440) = **37.5**。
**35 ではない**（約2.5半音ずれ）。上限は L = 0.15 m → 571.7 Hz → 73.5 → 74 で正しい。

併せて、範囲外ノートの扱い（クランプ / 無音 / オクターブ折返し）が未定義。
クランプだと押鍵と発音が食い違う。

### R11. `wallLoss` の適用点が未定義（§4.5、設計書 :177）

「1往復あたりのゲイン」とあるが、片道の遅延線2本それぞれに `√wallLoss` を掛けるのか、
往復で1箇所に `wallLoss` を掛けるのかが不明。0.90 – 1.0 という範囲の解釈が変わる。

### R12. `oversample` 切替時の状態が未定義（§4.6、設計書 :184）

1× ↔ 2× で D が倍/半分になり、リード IIR 係数・反射フィルタ係数もすべて変わる。
遅延線の作り直し = 音切れ。演奏中に切替えられる UI なので挙動を決める必要がある。

併せて:

- バッファ確保サイズの記述が無い（最大 D = 1.2 m × 2× = 336 サンプル + 補間マージン）
- snapshot の 1024 サンプルが表す時間長が 2× では半分（10.7 ms）になる
  → 可視化の時間軸が倍率で変わる

### R13. 双一次変換のプリワープが未記述（§4.1、設計書 :116）

`reedFreq` 上限 5000 Hz @48 kHz、プリワープ無しだと共鳴が約 4820 Hz（−3.7%）に落ちる。
2200 Hz では −0.7% で無視できる。
スクイークは f_r 依存の要件なので、範囲上端でずれるのは望ましくない。

### R14. テスト7・8 と段取り1 が循環している（§9 :299-300 / §10 :314）

段取り1は「音を出す前に物理を固める」。
だがテスト7（γ を上げると比 2.7–3.3 へ跳ぶ）とテスト8（スクイーク）が成立する
パラメータ領域は §10-6 の実測まで未知。
テスト先行だと最初に失敗し、閾値を後付けで調整することになる。

**修正案**: テスト7・8 は段取り6の後に確定する旨を明記する。
または探索的テスト（「跳躍が起きる γ が存在する」のみを主張し、比の範囲は緩く取る）にする。

### R15. テスト6 の ±5% が根拠不明（§9、設計書 :297）

±5% = 0.85半音。同じ行で「損失とリードのリアクタンスで理論値よりやや低い」と認めている。
`bellCutoff` を下限 200 Hz まで下げた端では 5% を超えうる。
既定パラメータ限定である旨の記述が要る。
