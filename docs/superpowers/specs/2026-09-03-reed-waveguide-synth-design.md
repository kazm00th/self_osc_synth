# シングルリード自励振動 + デジタル導波路 楽音合成装置 — 設計書

2026-09-03

## 1. 目的

シングルリード（クラリネット）の**自励振動**部と、円筒管の**デジタル導波路**共鳴部を
連結したブラウザ実時間の楽音合成装置。MIDI キーボードで演奏でき、画面上のスライダーで
吹圧・管長・リードのパラメータを操作できる。

自励振動の4要素との対応:

| 要素 | 本装置での対応 |
|---|---|
| 直流エネルギー源 | 吹圧 γ（定圧、ゲートでエンベロープを掛ける） |
| 非線形要素 | リード弁（1自由度の動特性 + Bernoulli 流 + ビーティング） |
| 線形・受動の共鳴器 | 円筒閉管の双方向遅延線 + 反射フィルタ |
| フィードバック | 管内圧 → リード両端の圧力差 → 流量 → 管へ |

### 中心要件

1. **「音が裏返る現象」を自励振動部のパラメータで再現できること。**
   - 12度の裏返り: 円筒閉管の共鳴は f, 3f, 5f… 吹圧 γ を上げる、または ζ を下げる（締める）と
     1次モードが維持できず3次モードへ跳ぶ。
   - スクイーク: リード自己共鳴 f_r を下げると、管のどのモードでもなくリード共鳴に引き込まれる。
   - レジスターキーは実装しない（パラメータ起因の裏返りが要件のため）。
2. 自励振動部の振動状態が見えること（相図、非線形特性 + 動作点）。
3. 導波路内の共鳴状態が見えること（管内の定在波）。

### 非目標

円錐管（サックス）、トーンホール列、多音（管楽器は単音）、レジスターキー、
オフラインレンダリング、音色プリセットの作り込み。

## 2. 前提と制約

- **Web MIDI API は secure context 必須。`file://` では動かない**（`localhost` は secure 扱い）。
  AudioWorklet の `addModule()` も `file://` では CORS で弾かれやすい。
  → 姉妹プロジェクト（telegraph_eq 等）の「HTML をダブルクリックして開く」流儀は採れず、
  **ローカル配信が前提**。
- **SharedArrayBuffer は使わない**。COOP/COEP ヘッダが必要で `http.server` では出せない。
  worklet → main のデータは `port.postMessage`。
- **Node は `D:\node-v24.20.0-win-x64\node.exe`（v24.20.0）にある**（2026-09-03 に動作確認）。
  `node --test` が使えるので DSP の単体テストはヘッドレスで走らせる。
  ESM 構文は Node 24 が自動判定するので **`package.json` は不要**（`.js` のまま `import` が通る）。
- npm・バンドラ・TypeScript は使わない（姉妹プロジェクトの build-free を維持）。
  `node` はテスト実行にのみ使い、ビルドには使わない。
- Python は PATH 上が Microsoft Store のエイリアスなので、サーバ起動には conda 環境
  `myenv311` の python を使う。

## 4. DSP コア

無次元化する。圧力は静的ビーティング圧 `p_M` で、流量は特性インピーダンス `Z_c` で正規化。
内部は無次元、UI 表示のみ物理単位を併記する。

### 4.1 リード（1自由度、状態あり）

```
(1/ωr²)·x'' + (qr/ωr)·x' + x = 1 − Δp̃
```

- `x` = 正規化リード開口。x=1 が静止開口、**x ≤ 0 でビーティング（完全閉鎖）**
- `Δp̃ = γ − p̃`（γ = 吹圧、p̃ = マウスピース内圧、ともに無次元）
- `ωr = 2π·reedFreq`、`qr = 1/reedQ`
- 離散化は**双一次変換による2極 IIR**。Δp̃ を与えれば線形なので RK4 は不要。
  ωr ≈ 2π·(300–5000) rad/s、fs ≥ 48 kHz で無条件安定。
- ビーティング中（x < 0）は `qr` を `contactQ` 倍にする（接触損失）。
  減衰係数が切り替わるので、**IIR 係数を「開放時」「接触時」の2組あらかじめ計算しておき、
  サンプルごとに選択する**（毎サンプルの係数再計算は避ける）。

### 4.2 非線形流量（Bernoulli）

```
ũ = ζ · max(x, 0) · sign(Δp̃) · √|Δp̃|
```

`ζ` = リード開口パラメータ。`ζ = Z_c·w·H·√(2/(ρ·p_M))`。締めると小、緩めると大。

### 4.3 導波路との結合 — 反復不要の閉形式

マウスピース端で `p̃ = p⁺ + p⁻`、`ũ = p⁺ − p⁻`。`p⁻` は遅延線から既知。
`b = γ − 2p⁻` と置くと `Δp̃ = b − ũ` となり、4.2 は **ũ の二次方程式**になる:

```
X  = max(x, 0)
s  = ζ²·X²
b  = γ − 2·p⁻

b ≥ 0 : ũ = ( −s + √(s² + 4·s·b) ) / 2      （Δp̃ ≥ 0, 順流）
b < 0 : ũ = (  s − √(s² − 4·s·b) ) / 2      （Δp̃ < 0, 逆流）
p⁺ = ũ + p⁻
p̃  = p⁺ + p⁻
```

反復もテーブルも不要。1サンプルあたり `sqrt` 1回。`s = 0`（ビーティング中）なら `ũ = 0`。

### 4.4 1サンプルの更新順序

代数ループを作らないため、順序を固定する:

```
1. p⁻ ← 遅延線の出力（ベル側から戻ってきた波、線形補間）
2. X ← max(x, 0)                       ← x は前サンプルで求めた値
3. ũ ← 4.3 の閉形式で解く
4. ũ += noise · (|ũ| + 0.02) · (乱数 −1..1)   ← 乱流ノイズ。ノイズを足してから p⁺ を作る
5. p⁺ = ũ + p⁻ ,  p̃ = p⁺ + p⁻          ← 手順4の後に確定させる（順序を守らないと p⁺ が古くなる）
6. p⁺ を遅延線へ書き込む
7. Δp̃ = γ − p̃ でリード IIR を1ステップ進めて x を更新（開放/接触の係数を選択）
8. ベル端: 遅延線の他端を反射フィルタに通して折り返す
9. 出力 ← ベルの透過成分 → DC ブロッカ → tanh リミッタ

ノイズ項の `+ 0.02` は加算的な床。純粋な流量比例だと ũ=0 で恒久的に無音のままになり、
発音の立ち上がりが不確実になる。床があると発音前の「息の音」も出て音楽的にも正しい。
```

### 4.5 導波路（円筒閉管）

- 双方向遅延線1組、片道 `D = L·fs_internal / c` サンプル。`c = 343 m/s`（20 °C）。
- 円筒閉管は1往復で符号が1回反転するので**2往復で位相が戻る** → `f0 = fs/(4D)`。
  L=0.6 m, c=343, fs=48 kHz なら D ≈ 84、f0 ≈ 143 Hz。
- 端数遅延は**線形補間**。管長を連続的に動かす要件があるためオールパスは不採用
  （係数を動かすと過渡が出る）。`D ≥ 2` サンプルを保証するようクランプする。
- ベル反射: `R(z) = −(1−a)/(1 − a·z⁻¹)`、`a = exp(−2π·bellCutoff / fs_internal)`。
  直流で `R = −1`（開管端の完全反転反射）、高域で `R → 0`。
  **高域ほど放射して戻らない** → 高次モードほど損失が大きく、これが裏返りの閾値を作る本体。
- 管壁損失: 広帯域ゲイン `wallLoss`（`bellCutoff` とは独立）。
- 出力 = ベルに到達した進行波 `p⁺_bell` の**透過分** `p⁺_bell + R(p⁺_bell)`
  （= `(1+R)` を `p⁺_bell` に適用したもの）+ 1次ハイパス（放射 ≈ dp/dt）。
- 最終段に DC ブロッカと `tanh` ソフトリミッタ。

### 4.6 オーバーサンプリング

非線形（`sqrt` と閉鎖クリップ）がエイリアスを生む。**1× / 2× のトグル**。

- 2× では `fs_internal = 2·fs`。遅延線長 `D`、リード IIR 係数、反射フィルタ係数はすべて
  `fs_internal` で計算する。
- 出力の間引きは **15 タップの窓関数付き sinc ハーフバンド FIR**。
  入力側の補間は不要（「入力」は緩慢に変化するパラメータのみで、保持でよい）。
- **既定値は実測で決める。未測定のまま既定値を置かない。**

## 5. パラメータ

すべて `AudioParam`（`parameterDescriptors`）。`src/params.js` の1つの表から
スライダーもラベルも生成する。パラメータ追加＝表に1行。

| id | 表示 | 範囲 | 既定 | 意味 |
|---|---|---|---|---|
| `gamma` | 吹圧 γ | 0 – 1.0 | ゲート駆動 | γ = p_mouth / p_M |
| `zeta` | リード開口 ζ | 0.05 – 0.8 | 0.25 | アンブシュア |
| `tubeLength` | 管長 L | 0.15 – 1.2 m | 0.6 | f0 = c/(4L) |
| `reedFreq` | リード共鳴 f_r | 300 – 5000 Hz | 2200 | 下げるとスクイーク |
| `reedQ` | リード Q | 0.5 – 20 | 3 | 低いと準静的挙動へ |
| `contactQ` | 接触時の減衰倍率 | 1 – 20 × | 4 | ビーティング中の損失 |
| `bellCutoff` | ベル反射カットオフ | 200 – 5000 Hz | 1500 | 低いと裏返りにくい |
| `wallLoss` | 管壁損失 | 0.90 – 1.0 | 0.995 | 1往復あたりのゲイン |
| `noise` | 乱流ノイズ | 0 – 0.05 | 0.008 | 流量比例 |

UI のみ（AudioParam ではない）: `attack` / `release`（ms）、`oversample`（1×/2×）。

**物理単位の併記について**: `p_M ≈ 5 kPa`、`c = 343 m/s` を仮定して
γ → cmH2O、L → Hz を併記する。これは**目安の換算であって較正された測定値ではない**。
UI にもその旨を出す。

## 6. MIDI と演奏

- `navigator.requestMIDIAccess()`。複数入力があればドロップダウンで選択。
- ノート番号 → `f = 440·2^((n−69)/12)` → `L = c/(4f)` を `setValueAtTime`。
  範囲外はクランプ（L 0.15–1.2 m ≒ MIDI 35–74）。
- ゲート → `gamma.setTargetAtTime()`。**息のエンベロープ = 吹圧そのもの**なので物理的に正しく、
  立ち上がりの過渡（チフ音）が自然に出る。ベロシティ → γ のピーク値。
- **モノフォニック・後着優先**。押している鍵のスタックを持ち、離すと直前の音へ戻る。
- CC2（ブレスコントローラ）→ γ の倍率。
- MIDI 非対応/拒否 → QWERTY 鍵盤にフォールバック（`z s x d c…` の半音配列）+ 画面に表示。

**裏返ると鳴る音は管の基音の3倍になる。つまり「押した鍵より12度上が鳴る」のは
バグではなく要件どおりの挙動。** 上部に「管の f0 / 実際に鳴っている f0 / 比」を出して
裏返りインジケータにする。実際の f0 は `AnalyserNode` のスペクトルのピークから推定し、
`c/(4L)` との比を表示する（比 ≈1 なら第1レジスタ、≈3 なら第2レジスタ）。

### 自動テスト

1. 閉形式の流量解が 4.2 の非線形式を満たす（残差 < 1e-10）— γ, ζ, X, p⁻ の格子で総当たり
2. `ũ` の符号が `Δp̃` の符号と一致
3. `X = 0`（ビーティング中）で `ũ = 0`
4. `γ = 0` で発振しない（静止へ減衰）
5. **発振閾値が存在する** — γ を掃引して無振動→振動の境界が `0.2 < γ < 0.6` に1つある。
   （準静的理論値は 1/3 だが、リード動特性と損失で閾値はずれる。値を固定で決め打ちしない。）
6. 定常 f0 が `fs/(4D)` の **±5%** 以内。
   （損失とリードのリアクタンスで実際の発音は理論値よりやや低い。実クラリネットモデルでも同様。）
7. **γ を上げると f0 が約3倍へ跳ぶ**（比が 2.7–3.3 に入る）= 12度の裏返り
8. `reedFreq` を下げるとリード共鳴近傍へ引き込まれる（スクイーク）
9. パラメータ範囲の端を総当たりして NaN/Inf が出ない
10. 遅延線の線形補間が整数 `D` で厳密一致

### 手動受け入れ基準

- MIDI 鍵盤で発音、レイテンシが許容範囲
- 吹圧を**ゆっくり**上げる → 閾値で鳴り始め、さらに上げると12度上へ裏返る
- `reedFreq` を下げるとスクイーク
- 4パネルが 30 fps 前後で破綻なく更新
- CPU 実測 → `oversample` の既定値を決定
