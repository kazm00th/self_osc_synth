# シングルリード自励振動 + デジタル導波路 楽音合成装置 — 設計書

初版 2026-09-03 / 改訂 2026-09-04（[レビュー](./2026-09-04-reed-waveguide-synth-design-review.md) R1–R23 と自動テストのカバレッジ検討を反映）

## 1. 目的

シングルリード（クラリネット）の**自励振動**部と、円筒管の**デジタル導波路**共鳴部を
連結したブラウザ実時間の楽音合成装置。MIDI キーボードで演奏でき、画面上のスライダーで
吹圧・管長・リードのパラメータを操作できる。

自励振動の4要素との対応:

| 要素 | 本装置での対応 |
|---|---|
| 直流エネルギー源 | 吹圧 γ（ノート持続中はほぼ定圧、ノートオン/オフでランプ） |
| 非線形要素 | リード弁（1自由度の動特性 + Bernoulli 流 + ビーティング） |
| 線形・受動の共鳴器 | 円筒閉管の双方向遅延線 + 反射フィルタ |
| フィードバック | 管内圧 → リード両端の圧力差 → 流量 → 管へ |

### 中心要件

1. **「音が裏返る現象」を自励振動部のパラメータで再現できること。**
   - 12度の裏返り: 円筒閉管の共鳴は f, 3f, 5f… 主に **吹圧 γ を上げる**と、
     加えて `bellCutoff` を上げて高次モードの放射損失を下げる、あるいはアンブシュア ζ を
     調整すると、1次モードを維持できず3次モードへ跳ぶ。
     **どのパラメータ領域で起きるかは §10 手順6 で実測する。要件は「自励振動部の
     パラメータ操作で 1次→3次 の跳躍が起こせること」であって、特定の1パラメータでの
     単調な挙動までは規定しない。**
   - スクイーク: リード自己共鳴 f_r を下げていくと、管のどのモードでもなく
     リード共鳴近傍に引き込まれる。
   - レジスターキーは実装しない（パラメータ起因の裏返りが要件のため）。
2. 自励振動部の振動状態が見えること（相図、非線形特性 + 動作点）。
3. 導波路内の共鳴状態が見えること（管内の定在波）。

### 非目標

円錐管（サックス）、トーンホール列、多音（管楽器は単音）、レジスターキー、
オフラインレンダリング、音色プリセットの作り込み、リード運動による流量項（§4.2 参照）。

## 2. 前提と制約

- **Web MIDI API は secure context 必須。`file://` では動かない**（`localhost` は secure 扱い）。
  AudioWorklet の `addModule()` も `file://` では CORS で弾かれやすい。
  → 姉妹プロジェクト（telegraph_eq 等）の「HTML をダブルクリックして開く」流儀は採れず、
  **ローカル配信が前提**。
- **対象ブラウザ**: Chrome / Edge（主対象、Web MIDI は permission プロンプト）。
  Firefox 108+ と Safari 17.4+ は Web MIDI 対応済みだが**未検証**。それ以外は
  QWERTY フォールバック（§6）で鍵盤なしでも鳴る。
- **SharedArrayBuffer は使わない**。COOP/COEP ヘッダが必要で `http.server` では出せない。
  worklet → main のデータは `port.postMessage`。
- **Node は `D:\node-v24.20.0-win-x64\node.exe`（v24.20.0）にある**（2026-09-03 に動作確認）。
  `node --test` が使えるので DSP の単体テストはヘッドレスで走らせる。
  ESM 構文は Node 24 が自動判定するので **`package.json` は不要**（`.js` のまま `import` が通る）。
- npm・バンドラ・TypeScript は使わない（姉妹プロジェクトの build-free を維持）。
  `node` はテスト実行にのみ使い、ビルドには使わない。
- Python は PATH 上が Microsoft Store のエイリアスなので、サーバ起動には conda 環境
  `myenv311` の python を使う。

## 3. アーキテクチャ

### スレッド分担

| | 担当 | 動作 |
|---|---|---|
| audio thread（AudioWorkletGlobalScope） | 物理モデル全部 | `sampleRate`（通常 48 kHz）、128 サンプルブロック |
| main thread | UI・Web MIDI・Canvas 4枚 | `requestAnimationFrame` |

**main → worklet**: `AudioParam`（`parameterDescriptors`）。

- `gamma` と `tubeLength` は **a-rate**。演奏中に滑らかに動かすため。k-rate は
  128 サンプル毎の階段（2.67 ms @48 kHz）でクリック源になる。
- それ以外（`zeta`, `reedFreq`, `reedQ`, `contactQ`, `bellCutoff`, `wallLoss`, `noise`）は
  k-rate で可。動かしても過渡が問題になりにくい。
- `tubeLength` の実効遅延長 `D` は worklet 内で1極グライド（時定数 ~15 ms）を掛け、
  a-rate でもノートオン時の飛びを抑える（§4.5, §6）。

**worklet の出力は2系統**（`numberOfOutputs: 2`, `outputChannelCount: [1, 1]`）:

- `out[0]` = 放射音（§4.5 のベル透過音）→ `destination`
- `out[1]` = マウスピース内圧 `p̃` → 可視化用 `AnalyserNode` のみに接続。`destination` へは繋がない

`p̃` は worklet 内部量なので、これを外に出さないと `AnalyserNode` で波形・スペクトルが取れない。

**worklet → main**: `port.postMessage` を約 30 Hz（snapshot、§7）。
**audio thread では一切アロケートしない** — コンストラクタで確保したバッファを使い回し、
structured clone に任せる。1メッセージ約 18 KB × 30 Hz ≈ 550 KB/s。

## 4. DSP コア

無次元化する。圧力は静的ビーティング圧 `p_M` で、流量は特性インピーダンス `Z_c` で正規化。
内部は無次元、UI 表示のみ物理単位を併記する。

### 4.1 リード（1自由度、状態あり）— 状態空間・台形則

連続系:

```
x'' + qr·ωr·x' + ωr²·x = ωr²·(1 − Δp̃)
```

- `x` = 正規化リード開口。x=1 が静止開口、**x ≤ 0 でビーティング（完全閉鎖）**
- `Δp̃ = γ − p̃`（γ = 吹圧、p̃ = マウスピース内圧、ともに無次元）
- `ωr = 2π·reedFreq`、`qr = 1/reedQ`（減衰。SVF 記法の 2R に相当）

**直接形の2極 IIR は使わない**。理由:

- §7 パネル1 が `(x, x')` の相図を要求する。直接形の内部状態は `(x, x')` ではない。
- 開放/接触の係数切替が `x = 0` 交差ごと（毎周期2回、音声レート）に起きる。直接形は
  係数を切替えると内部状態の物理的意味が変わり、過渡が乗る。不安定化もありうる。

**台形則（TPT）の状態変数フィルタ形**にする。状態 `(s1, s2)` がそのまま `(x', x)` の意味を持ち、
係数切替が連続になる。周波数プリワープも内蔵。

```
g  = tan(π · reedFreq / fsInternal)          ← プリワープ済み（reedFreq 上端 5 kHz でずれない）
k  = qr            （開放時）  /  qr · contactQ （x<0 の接触時）
a1 = 1 / (1 + g·(g + k))
a2 = g · a1
a3 = g · a2

  ── 1 サンプル（入力 u = 1 − Δp̃）──
  v3 = u − s2
  v1 = a1·s1 + a2·v3
  v2 = s2 + a2·s1 + a3·v3
  s1 = 2·v1 − s1
  s2 = 2·v2 − s2
  x  = v2                    （lowpass 状態出力）
  x' = ωr · v1               （bandpass から速度、snapshot 用）
```

- `a1,a2,a3` は `k` にのみ依存する。開放時・接触時の2組を**あらかじめ計算**しておき、
  サンプルごとに `x` の符号で選択する（毎サンプルの `tan` 再計算は避ける）。
- `reedFreq` は k-rate なので変化時のみ `g` と両係数組を更新。
- 静止（γ=0, p̃=0 → u=1）で `x → 1`（LP の DC 利得 1）。§4.1 の「静止開口 x=1」と整合。

### 4.2 非線形流量（Bernoulli）

```
ũ = ζ · max(x, 0) · sign(Δp̃) · √|Δp̃|
```

`ζ` = リード開口パラメータ。`ζ = Z_c·w·H·√(2/(ρ·p_M))`。締めると小、緩めると大。

**単純化**: リード運動そのものによる流量項 `~ w·H·(dx/dt)` は入れない。無くても
発振はする（McIntyre–Schumacher–Woodhouse でもしばしば省く）。非目標に明記。

### 4.3 導波路との結合 — 反復不要の閉形式

マウスピース端で `p̃ = p⁺ + p⁻`、`ũ = p⁺ − p⁻`。`p⁻` は遅延線から既知。
`p̃ = ũ + 2p⁻` なので `Δp̃ = γ − p̃ = (γ − 2p⁻) − ũ`。`b = γ − 2p⁻` と置くと
`Δp̃ = b − ũ` となり、4.2 は **ũ の二次方程式**になる:

```
X  = max(x, 0)
s  = ζ²·X²
b  = γ − 2·p⁻

b ≥ 0 : ũ = ( −s + √(s² + 4·s·b) ) / 2      （Δp̃ ≥ 0, 順流）
b < 0 : ũ = (  s − √(s² − 4·s·b) ) / 2      （Δp̃ < 0, 逆流）
```

`sign(b) = sign(Δp̃)` が常に成り立つので、分岐条件は `b` の符号でよい。
反復もテーブルも不要。1サンプルあたり `sqrt` 1回。`s = 0`（ビーティング中）なら `ũ = 0`。
ここで求めた `ũ` から `p⁺` を作る手順は §4.4（ノイズ注入があるので確定は §4.4 手順5）。

### 4.4 1サンプルの更新順序

代数ループを作らないため、順序を固定する:

```
1. p⁻ ← 遅延線の出力（ベル側から戻ってきた波、線形補間）
2. X ← max(x, 0)                       ← x は前サンプルで求めた値
3. ũ ← 4.3 の閉形式で解く
4. ũ += noise · (|ũ| + 0.02) · (乱数 −1..1)   ← 乱流ノイズ。p⁺ を作る前に足す
5. p⁺ = ũ + p⁻ ,  p̃ = p⁺ + p⁻          ← 手順4の後に確定
6. p⁺ を遅延線へ書き込む
7. Δp̃ = γ − p̃ でリード状態空間を1ステップ進めて x, x' を更新（開放/接触係数を選択）
8. ベル端: 遅延線の他端を反射フィルタ + wallLoss に通して折り返す（§4.5）
9. out[1] ← p̃
   out[0] ← ベル透過音 → DC ブロッカ → tanh リミッタ
```

ノイズ項の `+ 0.02` は加算的な床。純粋な流量比例だと ũ=0 で恒久的に無音のままになり、
発音の立ち上がりが不確実になる。床があると発音前の「息の音」も出て音楽的にも正しい。

### 4.5 導波路（円筒閉管）

- 双方向遅延線1組、片道 `D = L·fsInternal / c` サンプル。`c = 343 m/s`（20 °C）。
  `L` は §4.5 冒頭のグライド後の値を使う（下記）。
- **`D` の範囲**: `L` 0.15–1.2 m, `c` 343, 1× で **D ≈ 21–168**、2× で 42–336。
  バッファは最大 336 + 補間マージンを見て **512 サンプル**確保。
- 円筒閉管は1往復で符号が1回反転するので**2往復で位相が戻る** → `f0 = fsInternal/(4D) = c/(4L)`。
  L=0.6 m なら f0 ≈ 143 Hz、D ≈ 84（48 kHz, 1×）。
- リード端の反射 ≈ **+1**（発声中はほぼ閉端＝高インピーダンス、圧力の腹）。
- ベル反射: `R(z) = −(1−a)/(1 − a·z⁻¹)`、`a = exp(−2π·bellCutoff / fsInternal)`。
  直流で `R = −1`（開管端の完全反転反射）、高域で `R → 0`。
  **高域ほど放射して戻らない** → 高次モードほど損失が大きく、これが裏返りの閾値を作る本体。
- **`wallLoss` の適用点**: 1往復あたり1回、ベル反射と同じ地点で `wallLoss·R(z)` として掛ける。
  範囲 0.90–1.0 は「1往復での広帯域ゲイン」。
- 端数遅延は**線形補間**。管長を連続的に動かす要件があるためオールパスは不採用
  （係数を動かすと過渡が出る）。`D ≥ 2` をクランプ。
- **`D` のグライド**: `tubeLength` が変わっても `D` は1極グライド（時定数 ~15 ms）で追従。
  ノートオン時の管長飛び・レガートのポルタメントを兼ねる。遅延線のクリアはしない
  （息が抜ければ前の音は減衰済み、抜けなければレガートとして自然）。
- **出力**: ベルに到達した進行波 `p⁺_bell` の透過分 `(1 + R)·p⁺_bell`。
  `(1 + R)` は DC で 0・高域で ~1 の**1次ハイパスそのもの**なので、これが放射微分
  （放射 ≈ dp/dt）の役を果たす。**追加のハイパスは掛けない**。
  `out[0]` は `(1+R)` 透過音 → DC ブロッカ（tanh 後の偶数次対策の保険）→ tanh リミッタ。

### 4.6 オーバーサンプリング

非線形（`sqrt` と閉鎖クリップ）がエイリアスを生む。**1× / 2× のトグル**。

- 2× では `fsInternal = 2·fs`。遅延線長 `D`、リード係数 `g/a1..a3`、反射フィルタ係数 `a` は
  すべて `fsInternal` で計算する。
- 出力の間引きは **15 タップの窓関数付き sinc ハーフバンド FIR**。
  入力側の補間は不要（「入力」は緩慢に変化するパラメータのみで、保持でよい）。
- **切替時**: 係数と `D` を再計算し、遅延線の中身を新レートへ線形リサンプル、
  さらに `out[0]` を 5 ms フェード（切替は明示的なユーザー操作なので短い無音は許容）。
- snapshot に `fsInternal` を含める。2× では snapshot 1024 サンプルが表す時間が半分（10.7 ms）に
  なるので、可視化の時間軸は `fsInternal` で換算する（§7）。
- **既定値（1× か 2×）は §10 手順6 の CPU 実測で決める。未測定のまま既定値を置かない。**

## 6. MIDI と演奏

### ノート → 管長

- ノート番号 → `f = 440·2^((n−69)/12)` → `L = c/(4f)`。
- クランプ `L ∈ [0.15, 1.2] m`（≒ **MIDI 38–74**。L=1.2 m → 71.5 Hz → MIDI 37.5、
  L=0.15 m → 572 Hz → MIDI 73.5）。範囲外のノートはクランプし、
  **実際に鳴っているピッチを上部バーに表示**（押鍵と発音がずれるため）。
- `tubeLength` AudioParam へは `setValueAtTime`。worklet 側の 15 ms グライド（§4.5）が
  遅延線の飛びを吸収する。
- **モノフォニック・後着優先**。押している鍵のスタックを持ち、離すと直前の音へ戻る（レガート）。

### ゲート・ベロシティ → 実効吹圧 γ

γ は**倍率の積み上げをしない**。表現ソースの値を `[γ_base, γ_ceiling]` の内分点へ写像し、
そこへノートオン/オフのゲート包絡を掛けるだけ。すべて 1.0 以下に収まる（クランプ不要）。

```
γ_base    = 0.30 + velocity01 · 0.25         → [0.30, 0.55]  演奏可能な第1レジスタ域
γ_ceiling = 0.95                             静的閉鎖 1.0 の手前。跳躍閾値より上
expr01    = 選択された表現ソースの現在値 [0..1]
              ブレス(CC2): CC2/127            静止 0（息を入れないと expr01=0）
              モジュレーション(CC1): CC1/127   ホイール静止 0
              なし: 0
γ_target  = γ_base + expr01 · (γ_ceiling − γ_base)
γ(t)      = gateEnv(t) · γ_target            gateEnv: ノートオンで 0→1（τ=attack）、
                                             オフで 1→0（τ=release）
```

- `expr01 = 0`（コントローラ静止）で `γ_target = γ_base` → 通常発音。無音にはならない。
- コントローラを上げると `γ_target → 0.95` へ寄り、**意図的に12度へ追い込める**。
  ブレスとモジュレーションで写像は同じ（どちらも静止 0 → γ_base）。
- ソース切替時は現在の `expr01` を保持して `γ_target` が飛ばないようにする。
- main 側で `γ_target` を計算し `gamma.setTargetAtTime(γ_target, now, τ_short≈0.02)` を呼ぶ。
  演奏中のコントローラ移動もこれで滑らかに反映。
- CC2 は多くのブレスコントローラの既定。CC1 は全鍵盤にある。

> **注**: この写像は初版〜コミット `6def6b2` の「倍率 1.0–1.5」方式を置き換える
> （倍率方式は AudioParam 上限 1.0 で天井打ちして「12度へ追い込む」が効かなかった。R6）。

### 裏返りインジケータ

上部バーに「管の f0（= c/4L）/ 実際に鳴っている f0 / 比」を出す。

- 実 f0 は `out[1]`（p̃）を **`AnalyserNode` の `getFloatTimeDomainData` から自己相関**、
  または倍音列マッチング（f0 候補に対し f, 3f, 5f のエネルギー総和を評価）で推定する。
  **スペクトルのピーク検出は使わない** — クラリネット波形は3次が基音より強いことが常で、
  第1レジスタでも「比 ≈ 3」と誤判定する。bin 分解能（fftSize 2048 @48 kHz で 23 Hz）も
  低音（71 Hz）に対して粗い。
- 比 ≈ 1 なら第1レジスタ、≈ 3 なら第2レジスタ。

### フォールバック

Web MIDI 非対応/拒否 → QWERTY 鍵盤（`z s x d c…` の半音配列）+ 画面に表示。

## 7. 可視化

| パネル | 中身 | データ源 |
|---|---|---|
| 1. リード相図 | `(x, x')` の軌跡をフェード付きで。**x=0 線**（ビーティング境界）を引く。リミットサイクル、閉鎖中の平坦部、裏返り時の軌道変化が見える | snapshot（`x`, `xd`） |
| 2. 非線形特性 + 動作点 | 準静的特性曲線 `ũ(Δp̃)` と、その上を回る動作点の軌跡（直近 ~21 ms、低音では2周期未満のこともある） | snapshot（`dp`, `u`） |
| 3. 管内の定在波 | `p⁺(z)`, `p⁻(z)`, 和 を管軸に沿って。左=リード端、右=ベル。**節・腹の数が 1→3 に変わる瞬間**が見える | snapshot（`pPlus`, `pMinus`） |
| 4. スペクトル / 時系列 | `p̃` の波形（~40 ms）とスペクトル。奇数倍音列と、基音が3倍へ飛ぶのが周波数軸で見える | **`AnalyserNode`（out[1]）** — FFT・時間波形とも main 側、audio thread に乗らない |

**snapshot の中身**（`port.postMessage`、約 30 Hz、Float32、約 18 KB）:

| フィールド | 長さ | 内容 |
|---|---|---|
| `fsInternal` | 1 | 現在の内部レート（時間軸換算用） |
| `x`, `xd` | 各 1024 | リード開口と速度。連続 1024 サンプル（送出間隔 33 ms のうち 21 ms 分。相図・特性図には非連続でも無害） |
| `dp`, `u` | 各 1024 | Δp̃ と ũ |
| `pPlus`, `pMinus` | 各 `min(D, 256)` | 遅延線の中身。`D < 256`（短管）なら全点、長管 2× では 256 へ間引き。パネル3側でキャンバス幅へ線形リサンプル |

計 ≈ 4×1024 + 2×256 + 1 = 4609 float32 ≈ 18 KB、×30 Hz ≈ 550 KB/s。

描画は 30 fps、キャンバスは 380×260 CSS px、`devicePixelRatio` は 2 で上限。

## 8. エラー処理

- `file://` で開かれたのを検出 → 「サーバ経由で開いてください」と表示（Web MIDI が動かないため）
- `AudioWorklet` 非対応 → メッセージ表示して停止
- Web MIDI 非対応/拒否 → QWERTY フォールバック
- **数値発散ガード**: `process()` の**ブロック末に1回**、`!isFinite(p̃) || |p̃| > 1e3` を検査。
  引っかかったらリード状態 `(s1,s2)` と遅延線を全ゼロにし、`port` で main へ通知、
  `out[0]` を無音から 5 ms でフェードイン。`wallLoss = 1.0` + γ 大 のような範囲の端で起こりうる。
- 最終段に `tanh` ソフトリミッタ（スピーカー保護）。

## 9. テスト

### 何を自動テストに選んだか

ブラウザも音響ハードも要らず、決定的で、DSP の純粋な関数として検証でき、
**中心要件（自励振動・12度の裏返り・スクイーク）に直結する**ものを選ぶ。
`node --test`（`node:test` + `node:assert/strict`、依存ゼロ）。
`tests/model.test.js` が `worklet/reed-tube-processor.js` から `ReedTubeModel` を直接 import
する（§3 のガードのおかげ。モデルのコピーは作らない）。

```
"D:\node-v24.20.0-win-x64\node.exe" --test
```

### 自動テスト

**閉形式ソルバ（§4.3）— 唯一の非自明な代数**

1. 閉形式解が §4.2 の非線形式を満たす（残差 < 1e-10）— γ, ζ, X, p⁻ の格子で総当たり
2. `ũ` の符号が `Δp̃` の符号と一致
3. `X = 0`（ビーティング中）で `ũ = 0`

**自励振動の素性**

4. `γ = 0` で発振しない（静止へ減衰）。数値エネルギー注入で「鳴ってしまう」モデルを弾く
5. 発振閾値が存在する — γ を掃引して無振動→振動の境界が `0.2 < γ < 0.6` に1つある
   （準静的理論値は 1/3 だが動特性と損失でずれる。値は決め打ちしない）
6. **既定パラメータで** 定常 f0 が `fsInternal/(4D)` の ±5 % 以内、かつ L に対して単調
   （端の `bellCutoff = 200 Hz` などでは 5 % を超えうるので既定パラメータ限定）

**中心要件（探索的。閾値の確定は §10 手順6 の後）**

7. パラメータ空間に **1次→3次の跳躍が存在する** — γ を上げる、または `bellCutoff` を
   上げる掃引で、実 f0 / (c/4L) の比が 1 近傍から 3 近傍（2.5–3.5）へ不連続に飛ぶ点がある。
   γ 単独で出なければ (γ, bellCutoff) の2次元掃引で探す
8. `reedFreq` を下限へ動かすと、発音周波数が管モード（c/4L の奇数倍）から外れ
   `reedFreq` 近傍へ寄る点がある（スクイーク）

**数値健全性**

9. パラメータ全範囲の端の組合せ（2次元グリッド）で 5 秒回して NaN/Inf が出ない
10. 遅延線の線形補間が整数 `D`（`delaySamples` 直接指定）で厳密一致
11. **ブロック境界不変性** — 同じ入力を 1 回の `process(N)` と N/128 回の `process(128)` で
    処理し、出力が一致（状態管理・ブロック継ぎ目のバグを検出）
12. **決定性** — 同じシード・同じ入力で 2 回走らせて出力ビット一致
13. **長時間振幅安定性** — 既定パラメータで 20 秒、定常後の RMS が最初の1秒と ±10 % 以内
    （ゆっくりした発散・減衰・振幅ドリフトを検出）
14. **共鳴器単体の受動性** — `γ = 0` でリード端にインパルスを入れ、遅延線のエネルギーが
    単調減少（`wallLoss ≤ 1` で利得を持たない）
15. **オーバーサンプリング整合** — 1× と 2× で定常 f0 が ±1 %、第1–5倍音の相対レベルが
    ±3 dB（2× 実装のリサンプル・係数換算のミスを検出）
16. **パラメータランプの滑らかさ** — `tubeLength` を 50 ms かけて端から端へ動かし、
    `out[0]` の隣接サンプル差が静定時の最大値の 3 倍を超えない（§4.5 グライドのクリック検出）

### この自動テストで検出できない不具合

**ブラウザ / 実時間経路**（→ 手動受け入れ基準へ）

- AudioWorklet の配線ミス、2出力ルーティング、`AnalyserNode` タップ、`port.postMessage` 経路
- a-rate パラメータ配列の読み違い（テストはオフラインでスカラー入力しがち）
- レイテンシ、MIDI の取りこぼし・和音時の挙動、`expressionSource` 切替の実挙動
- Canvas 4 枚が 30 fps で破綻しないか、`devicePixelRatio` 対応
- `oversample` を演奏中に切替えたときのフェードとグリッチ

**知覚・音楽的品質**（→ 耳で確認）

- 音色。テストは f0 と粗い振幅しか見ない。正しいピッチのまま「ブザー」でも通る。
  奇数偶数比・スペクトル重心・レジスタごとの音色は未検証
- アタックの過渡（チフ音）、発音の立ち上がり時間、ノートオンの「ポップ」
- レガートの繋がり、`D` グライドが速すぎ/遅すぎないか
- 裏返りの**ヒステリシス**（上げて跳ぶ γ と下げて戻る γ の差）、マルチフォニック、
  意図しないレジスタに**居着く**現象。テスト7は「跳躍が存在する」までしか見ない
- 通常演奏中に**不要なスクイーク・ワーブル**が出ないこと（テスト8はスクイークが
  出せることの確認であって、出ないことの保証ではない）

**性能**

- CPU が 1 ブロック時間に収まるか。正しいが重いモデル（常時 2×、うっかり O(D) の内側ループ）は
  テストを通る。§10 手順6 の実測で見る

**可視化の中身**

- snapshot の中身の正しさ、裏返りインジケータの f0 推定（自己相関/倍音マッチング）の精度、
  パネル3のリサンプル。インジケータが系統的に誤っていても全テストが通りうる

**参照比較の不在**

- 高オーバーサンプリング版や解析解との波形一致は見ていない。倍音振幅が 10 % ずれていても
  （テスト15 の ±3 dB より内側なら）通る。エイリアスの絶対量、DC ドリフトの絶対量は未評価

**2パラメータ以上の相互作用**

- テスト9・15 以外は 1 パラメータずつ。`reedFreq` 大 + 短管 + γ 大 のような角で
  起こる不安定・誤レジスタは、掃引を密な格子にしない限り漏れうる

### 手動受け入れ基準

- MIDI 鍵盤で発音、レイテンシが許容範囲
- 吹圧を**ゆっくり**上げる → 閾値で鳴り始め、さらに上げると12度上へ裏返る
- `reedFreq` を下げるとスクイーク
- レガートで音がクリックなく繋がる
- 通常演奏で不要なスクイーク・ワーブルが出ない
- 4パネルが 30 fps 前後で破綻なく更新
- CPU 実測 → `oversample` の既定値を決定
