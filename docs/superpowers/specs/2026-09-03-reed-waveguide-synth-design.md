## 1. 目的

シングルリード（クラリネット）の**自励振動**部と、円筒管の**デジタル導波路**共鳴部を
連結したブラウザ実時間の楽音合成装置。MIDI キーボードで演奏でき、画面上のスライダーで
吹圧・管長・リードのパラメータを操作できる。

自励振動の4要素との対応:

| 要素 | 本装置での対応 |
|---|---|
| 直流エネルギー源 | 吹圧 γ（ノート持続中はほぼ定圧、ノートオン/オフでランプ） |
| 非線形要素 | リード弁（1自由度の動特性 + Bernoulli 流 + ビーティング） |
| 線形・受動の共鳴器 | 円筒閉管の双方向遅延線 + 反射フィルタ |
| フィードバック | 管内圧 → リード両端の圧力差 → 流量 → 管へ |

### 中心要件

1. **「音が裏返る現象」を自励振動部のパラメータで再現できること。**
   - 12度の裏返り: 円筒閉管の共鳴は f, 3f, 5f… 主に **吹圧 γ を上げる**と、
     加えて `bellCutoff` を上げて高次モードの放射損失を下げる、あるいはアンブシュア ζ を
     調整すると、1次モードを維持できず3次モードへ跳ぶ。
     **どのパラメータ領域で起きるかは §10 手順6 で実測する。要件は「自励振動部の
     パラメータ操作で 1次→3次 の跳躍が起こせること」であって、特定の1パラメータでの
     単調な挙動までは規定しない。**
   - スクイーク: リード自己共鳴 f_r を下げていくと、管のどのモードでもなく
     リード共鳴近傍に引き込まれる。
   - レジスターキーは実装しない（パラメータ起因の裏返りが要件のため）。
2. 自励振動部の振動状態が見えること（相図、非線形特性 + 動作点）。
3. 導波路内の共鳴状態が見えること（管内の定在波）。

### 非目標

円錐管（サックス）、トーンホール列、多音（管楽器は単音）、レジスターキー、
オフラインレンダリング、音色プリセットの作り込み、
**リード運動による流量項**（§4.2）、**接触時の剛性増加**（§4.1）。

## 2. 前提と制約

- **Web MIDI API は secure context 必須。`file://` では動かない**（`localhost` は secure 扱い）。
  AudioWorklet の `addModule()` も `file://` では CORS で弾かれやすい。
  → 姉妹プロジェクト（telegraph_eq 等）の「HTML をダブルクリックして開く」流儀は採れず、
  **ローカル配信が前提**。
- **対象ブラウザ**: Chrome / Edge（主対象、Web MIDI は permission プロンプト）。
  Firefox 108+ と Safari 17.4+ は Web MIDI 対応済みだが**未検証**。それ以外は
  QWERTY フォールバック（§6）で鍵盤なしでも鳴る。
- **SharedArrayBuffer は使わない**。COOP/COEP ヘッダが必要で `http.server` では出せない。
  worklet → main のデータは `port.postMessage`。
- **Node は `D:\node-v24.20.0-win-x64\node.exe`（v24.20.0）にある**（2026-09-03 に動作確認）。
  `node --test` が使えるので DSP の単体テストはヘッドレスで走らせる。
  ESM 構文は Node 24 が自動判定するので **`package.json` は不要**（`.js` のまま `import` が通る）。
- npm・バンドラ・TypeScript は使わない（姉妹プロジェクトの build-free を維持）。
  `node` はテスト実行にのみ使い、ビルドには使わない。
- Python は PATH 上が Microsoft Store のエイリアスなので、サーバ起動には conda 環境
  `myenv311` の python を使う。

## 3. アーキテクチャ

### スレッド分担

| | 担当 | 動作 |
|---|---|---|
| audio thread（AudioWorkletGlobalScope） | 物理モデル全部 | `sampleRate`（通常 48 kHz）、128 サンプルブロック |
| main thread | UI・Web MIDI・Canvas 4枚 | `requestAnimationFrame` |

**main → worklet（AudioParam）**:

- `gamma`（表現ぶんの目標値）、`gate`（ノート包絡）、`tubeLength` は **a-rate**。
  k-rate は 128 サンプル毎の階段（2.67 ms @48 kHz）でクリック源になる。
- それ以外（`zeta`, `reedFreq`, `reedQ`, `contactQ`, `bellCutoff`, `wallLoss`, `noise`）は
  k-rate で可。
- `tubeLength` の実効遅延長 `D` は worklet 内で1極グライド（時定数 ~15 ms）を掛ける（§4.5）。

**main → worklet（port.postMessage）** — AudioParam にできない制御:

| type | 内容 |
|---|---|
| `setOversample` | `{ factor: 1 \| 2 }`。係数再計算・遅延線リサンプル・5 ms フェード（§4.6） |

**worklet → main（port.postMessage）**:

| type | 内容 |
|---|---|
| `snapshot` | 約 30 Hz。可視化データ（§7） |
| `diverged` | 発散ガードが作動した通知（§8） |

**audio thread では一切アロケートしない** — コンストラクタで確保したバッファを使い回し、
structured clone に任せる。1メッセージ約 18 KB × 30 Hz ≈ 550 KB/s。

**worklet の出力は2系統**（`numberOfOutputs: 2`, `outputChannelCount: [1, 1]`）:

- `out[0]` = 放射音（§4.5 のベル透過音）→ `destination`
- `out[1]` = マウスピース内圧 `p̃` → 可視化用 `AnalyserNode` のみに接続。`destination` へは繋がない

`p̃` は worklet 内部量なので、これを外に出さないと `AnalyserNode` で波形・スペクトルが取れない。
**2× 時は `out[1]` にも `out[0]` と同じデシメーションを掛ける**（§4.6）。

## 4. DSP コア

無次元化する。圧力は静的ビーティング圧 `p_M` で、流量は特性インピーダンス `Z_c` で正規化。
内部は無次元、UI 表示のみ物理単位を併記する。

### 4.1 リード（1自由度、状態あり）— 状態空間・台形則

連続系:

```
x'' + qr·ωr·x' + ωr²·x = ωr²·(1 − Δp̃)
```

- `x` = 正規化リード開口。x=1 が静止開口、**x ≤ 0 でビーティング（完全閉鎖）**
- `Δp̃ = γ − p̃`（γ = 吹圧、p̃ = マウスピース内圧、ともに無次元）
- `ωr = 2π·reedFreq`、`qr = 1/reedQ`（減衰。SVF 記法の 2R に相当）

**直接形の2極 IIR は使わない**。理由:

- §7 パネル1 が `(x, x')` の相図を要求する。直接形の内部状態は `(x, x')` ではない。
- 開放/接触の係数切替が `x = 0` 交差ごと（毎周期2回、音声レート）に起きる。直接形は
  係数を切替えると内部状態の物理的意味が変わり、過渡が乗る。不安定化もありうる。

**台形則（TPT）の状態変数フィルタ形**にする。状態 `(s1, s2)` がそのまま `(x', x)` の意味を持ち、
係数切替が連続になる。周波数プリワープも内蔵。

```
g  = tan(π · reedFreq / fsInternal)          ← プリワープ済み
ω_warped = 2 · fsInternal · g                ← 実効角周波数（≠ ωr、下記）
k  = qr            （開放時）  /  qr · contactQ （x<0 の接触時）
a1 = 1 / (1 + g·(g + k))
a2 = g · a1
a3 = g · a2

  ── 1 サンプル（入力 u = 1 − Δp̃）──
  v3 = u − s2
  v1 = a1·s1 + a2·v3
  v2 = s2 + a2·s1 + a3·v3
  s1 = 2·v1 − s1
  s2 = 2·v2 − s2
  x  = v2                    （lowpass 状態出力）
  x' = ω_warped · v1         （bandpass から速度、snapshot 用）
```

- **`x'` の係数は `ωr` ではなく `ω_warped = 2·fsInternal·g`**。TPT の内部積分器は
  プリワープ後の周波数に対応するため。`ωr` を使うと `reedFreq = 5 kHz @48 kHz` で
  **+3.73 %** のスケール誤差（2200 Hz で +0.70 %、300 Hz で +0.01 %）。
  用途は §7 パネル1 の可視化のみだが、正しい形が同コストなので `ω_warped` を使う。
- `a1,a2,a3` は `k` にのみ依存する。開放時・接触時の2組を**あらかじめ計算**しておき、
  サンプルごとに `x` の符号で選択する（毎サンプルの `tan` 再計算は避ける）。
  **選択に使う `x` は前サンプルの値**（§4.4 手順2 と同じ 1 サンプル遅れ）。実害はないが規約として固定する。
- `reedFreq` は k-rate なので変化時のみ `g`・`ω_warped`・両係数組を更新。
- 静止（γ=0, p̃=0 → u=1）で `x → 1`（LP の DC 利得 1）。「静止開口 x=1」と整合。
- **単純化**: 接触は減衰の増加（`contactQ`）のみで表す。実物のリードがレイに巻き付くときの
  **剛性増加は入れない**。したがって閉鎖中も `x` は 0 以下へ動き続ける（§7 パネル1 参照）。非目標に明記。

### 4.2 非線形流量（Bernoulli）

```
ũ = ζ · max(x, 0) · sign(Δp̃) · √|Δp̃|
```

`ζ` = リード開口パラメータ。`ζ = Z_c·w·H·√(2/(ρ·p_M))`。締めると小、緩めると大。

**単純化**: リード運動そのものによる流量項 `~ w·H·(dx/dt)` は入れない。無くても
発振はする（McIntyre–Schumacher–Woodhouse でもしばしば省く）。非目標に明記。

### 4.3 導波路との結合 — 反復不要の閉形式

マウスピース端で `p̃ = p⁺ + p⁻`、`ũ = p⁺ − p⁻`。`p⁻` は遅延線から既知。
`p̃ = ũ + 2p⁻` なので `Δp̃ = γ − p̃ = (γ − 2p⁻) − ũ`。`b = γ − 2p⁻` と置くと
`Δp̃ = b − ũ` となり、4.2 は **ũ の二次方程式**になる:

```
X  = max(x, 0)
s  = ζ²·X²
b  = γ − 2·p⁻

b ≥ 0 : ũ = ( −s + √(s² + 4·s·b) ) / 2      （Δp̃ ≥ 0, 順流）
b < 0 : ũ = (  s − √(s² − 4·s·b) ) / 2      （Δp̃ < 0, 逆流）
```

`sign(b) = sign(Δp̃)` が常に成り立つので、分岐条件は `b` の符号でよい。
反復もテーブルも不要。1サンプルあたり `sqrt` 1回。`s = 0`（ビーティング中）なら `ũ = 0`。
ここで求めた `ũ` から `p⁺` を作る手順は §4.4（ノイズ注入があるので確定は §4.4 手順5）。

**数値**: `b ≥ 0` 側は `s ≫ b` で桁落ちする形。等価で安定な形
`ũ = 2sb / (s + √(s² + 4sb))` を使ってよい。float64 では絶対誤差 ~1e-17 で実害はないが、
コストが同じなので安定形を採る。

### 4.4 1サンプルの更新順序

代数ループを作らないため、順序を固定する:

```
1. p⁻ ← 遅延線（ベル→リード側）の出力を読む（線形補間）
2. X ← max(x, 0)                       ← x は前サンプルで求めた値
3. ũ ← 4.3 の閉形式で解く
4. ũ += noise · (|ũ| + 0.02) · (乱数 −1..1)   ← 乱流ノイズ。p⁺ を作る前に足す
5. p⁺ = ũ + p⁻ ,  p̃ = p⁺ + p⁻          ← 手順4の後に確定
6. p⁺ を遅延線（リード→ベル側）へ書き込む
7. Δp̃ = γ − p̃ でリード状態空間を1ステップ進めて x, x' を更新（開放/接触係数を選択）
8. ベル端: リード→ベル線の出力を読み、wallLoss·R(z) を通してベル→リード線へ書き込む
9. out[0] ← (1+R)·p⁺_bell → tanh リミッタ → DC ブロッカ → 非有限サンプルを 0 に落とす
   out[1] ← p̃ → 非有限サンプルを 0 に落とす
```

ノイズ項の `+ 0.02` は加算的な床。純粋な流量比例だと ũ=0 で恒久的に無音のままになり、
発音の立ち上がりが不確実になる。床があると発音前の「息の音」も出て音楽的にも正しい。

### 4.5 導波路（円筒閉管）

#### 遅延線とループ全遅延の規約

**総ループ遅延を厳密に `2·D_eff` サンプルに固定する。** 規約:

- リード→ベル線とベル→リード線を**各 `D_eff` サンプル**とする（合計 `2·D_eff`）。
- 各線は循環バッファ。**書き込み位置 `w` に対し読み出し位置 = `w − D_eff`**
  （小数部は線形補間）。規約は**文の順序ではなくこのインデックス関係**で定める。
- **読み書きを記述する順序は総遅延に影響しない**（`D_eff ≥ 2` のため）。
  §4.4 が手順6 で書き手順8 で読むのは、この規約に反していない。
  順序で書くと「規約違反だ」と読まれて手順を入れ替えられる恐れがあるため、こう定める。
- **ポインタを先に進めてから読む実装（`tick()` 型の遅延線クラス）は使わない** —
  総遅延が `D_eff + 1` になり R28 の off-by-one が戻る。
- ベル反射フィルタ `R(z)` は1極再帰で、その `z⁻¹` は再帰の内部にあり
  **純粋遅延を追加しない**。リード端反射（+1）も遅延を追加しない。

この規約を決めないと総遅延が `2D` / `2D+1` / `2D+2` のいずれにもなりうる。
`f0` は総遅延の 2 倍（`4·D_eff` サンプル）で決まるので、2 サンプルの誤差は
**L=1.2 m で 0.30 %（0.05 半音）、L=0.15 m で 2.38 %（0.41 半音）**。
短管で系統的にピッチがずれる。テスト6 の ±5 % では検出できないので、
**総ループ遅延を直接測るテスト18** を置く。

#### 諸元

- 片道 `D = L·fsInternal / c` サンプル。`c = 343 m/s`（20 °C）。
- **`D` の範囲**: `L` 0.15–1.2 m, 1× で **D ≈ 21–168**、2× で 42–336。
  バッファは最大 336 + 補間マージンを見て **512 サンプル**確保。
- 円筒閉管は1往復で符号が1回反転するので**2往復で位相が戻る**
  → `f0 = fsInternal/(4·D_eff) = c/(4L)`。L=0.6 m なら f0 ≈ 143 Hz、D ≈ 84（48 kHz, 1×）。
- リード端の反射 ≈ **+1**（発音中はほぼ閉端＝高インピーダンス、圧力の腹）。
- ベル反射: `R(z) = −(1−a)/(1 − a·z⁻¹)`、`a = exp(−2π·bellCutoff / fsInternal)`。
  直流で `R = −1`（開管端の完全反転反射）、高域で `R → 0`。
  **高域ほど放射して戻らない** → 高次モードほど損失が大きく、これが裏返りの閾値を作る本体。
- **`wallLoss` の適用点**: 1往復あたり1回、ベル反射と同じ地点で `wallLoss·R(z)` として掛ける。
  範囲 0.90–1.0 は「1往復での広帯域ゲイン」。
- 端数遅延は**線形補間**。管長を連続的に動かす要件があるためオールパスは不採用
  （係数を動かすと過渡が出る）。`D_eff ≥ 2` をクランプ。
- **`D` のグライド**: `tubeLength` が変わっても `D_eff` は1極グライド（時定数 τ_D ≈ 15 ms）で追従。
  ノートオン時の管長飛び・レガートのポルタメントを兼ねる。遅延線のクリアはしない
  （息が抜ければ前の音は減衰済み、抜けなければレガートとして自然）。
  **制約**: `|dD/dt| < 1` サンプル/サンプルでないと読み出しポインタが逆行する。
  最大跳躍 `ΔD = 147`（21↔168）に対し τ_D=15 ms なら `147/(0.015·48000) = 0.204` で安全。
  **τ_D を 3 ms 未満にしてはならない。**
- **出力**: ベルに到達した進行波 `p⁺_bell` の透過分 `(1 + R)·p⁺_bell`。
  `(1 + R)` は DC で 0・高域で ~1 の**1次ハイパスそのもの**なので、これが放射微分
  （放射 ≈ dp/dt）の役を果たす。**追加のハイパスは掛けない**。
  `out[0]` の順序は **`(1+R)` 透過音 → `tanh` リミッタ → DC ブロッカ**。
  **DC ブロッカは `tanh` の後**でなければならない。`tanh` は奇関数だが、
  入力が平均 0 でも**波形が非対称なら出力に DC が出る**（クラリネットのビーティング波形は
  デューティ比が 50 % ではない）。例: +0.9 が 25 %・−0.3 が 75 %（入力平均 0）を通すと
  出力平均 −0.0394、出力 RMS 0.438、**|平均|/RMS = 9.0 %**。
  ブロッカを `tanh` の前に置くとこの DC を除去できず、チェーン末で測る
  §9 テスト19（DC < RMS の 1 %）が落ちる。
- **透過に `wallLoss` を掛けないのは意図的**。反射は `wallLoss·R`、透過は `(1+R)` なので
  `R` と `1+R` の相補関係が `wallLoss` の分だけ崩れる。`wallLoss` は本来
  管全体に分布する損失をベル1点へ集約した近似であり、透過（放射）成分に管壁損失を
  掛ける物理的理由はない。**バグではない。** テスト14（受動性）はこの前提で解釈する。

### 4.6 オーバーサンプリング

非線形（`sqrt` と閉鎖クリップ）がエイリアスを生む。**1× / 2× のトグル**。

- 2× では `fsInternal = 2·fs`。遅延線長 `D`、リード係数 `g`/`ω_warped`/`a1..a3`、
  反射フィルタ係数 `a` はすべて `fsInternal` で計算する。
- 間引きは **15 タップの窓関数付き sinc ハーフバンド FIR**。
  **`out[0]` と `out[1]` の両方に掛ける**（FIR 状態を2系統持つ）。
  `out[1]` は §6 の f0 推定と §7 パネル4 の唯一の入力なので、
  単純間引きでエイリアスさせると**自己相関による f0 推定が壊れる**。
  入力側の補間は不要（「入力」は緩慢に変化するパラメータのみで、保持でよい）。
- **切替時**（`port` の `setOversample`）: 係数と `D` を再計算し、遅延線の中身を
  新レートへ線形リサンプル、`out[0]` を 5 ms フェード
  （切替は明示的なユーザー操作なので短い無音は許容）。
  **リード状態 `(s1, s2)` は変換しない。** TPT では `s2 ≈ x`（位置）、
  `s1 ≈ x'/ω_warped` でどちらもレート不変。**そのままが正しいので触らないこと。**
  **一方 `D_eff`（グライドの内部状態）は即座に
  `D_eff ← D_eff × (fsInternal_new / fsInternal_old)` と再導出する。グライドさせない。**
  目標 `D` だけ更新して `D_eff` を放置すると、τ_D=15 ms のグライドが新目標へ向かうため、
  5 ms のフェード明けに約 40 ms かけて**1オクターブ下から上がってくるピッチグライド**が
  聞こえる（グライド静定 3·τ_D = 45 ms > フェード 5 ms）。
- snapshot に `fsInternal` を含める。2× では snapshot 1024 サンプルが表す時間が半分（10.7 ms）に
  なるので、可視化の時間軸は `fsInternal` で換算する（§7）。
- **既定値（1× か 2×）は §10 手順6 の CPU 実測で決める。未測定のまま既定値を置かない。**

## 5. パラメータ

`src/params.js` の1つの表からスライダーもラベルも生成する。パラメータ追加＝表に1行。

| id | 表示 | 範囲 | 既定 | rate | 意味 |
|---|---|---|---|---|---|
| `gamma` | 吹圧 γ（目標値） | 0 – 1.0 | **0** | a-rate | 表現ソース由来の持続レベル `γ_target`（§6）。γ>1 は静的閉鎖＝非発振なので上限 1.0 |
| `gate` | ノート包絡 | 0 – 1.0 | **0** | a-rate | ノートオン/オフの包絡。実効吹圧 = `gate · gamma`（worklet 内で積） |
| `zeta` | リード開口 ζ | 0.05 – 0.8 | 0.25 | k-rate | アンブシュア |
| `tubeLength` | 管長 L | 0.15 – 1.2 m | 0.6 | a-rate | f0 = c/(4L)。worklet 内で τ_D=15 ms グライド |
| `reedFreq` | リード共鳴 f_r | 300 – 5000 Hz | 2200 | k-rate | 下げるとスクイーク |
| `reedQ` | リード Q | 0.5 – 20 | 3 | k-rate | 低いと準静的挙動へ |
| `contactQ` | 接触時の減衰倍率 | 1 – 20 × | 4 | k-rate | ビーティング中の損失 |
| `bellCutoff` | ベル反射カットオフ | 200 – 5000 Hz | 1500 | k-rate | 上げると高次モード損失減 → 裏返りやすい |
| `wallLoss` | 管壁損失（1往復ゲイン） | 0.90 – 1.0 | 0.995 | k-rate | ベルで1回 |
| `noise` | 乱流ノイズ | 0 – 0.05 | 0.008 | k-rate | 流量比例 + 床 0.02 |

**`gamma` と `gate` を分けた理由**: 1本の `AudioParam` に対して
ゲート（τ = attack/release）と表現（τ_short ≈ 20 ms）を別々の時定数で書くと、
`setTargetAtTime` は後続呼び出しが先行を打ち切るため、
**リリース中にホイール／ブレスを動かすとリリースが取り消されて音が戻る**。
2本に分けて worklet 内で積を取れば時定数が衝突しない。

UI のみ（AudioParam ではない）: `attack` / `release`、`oversample`（1×/2×）、
`expressionSource`（ブレス CC2 / モジュレーション CC1 / なし）。

| UI 項目 | 範囲 | 既定 |
|---|---|---|
| `attack` | 1 – 500 ms | 20 ms |
| `release` | 1 – 1000 ms | 80 ms |

**時定数の規約**: `setTargetAtTime` の `τ = attack_ms / 3000`（秒）。
`attack_ms` 経過で目標の約 95 %（`1 − e⁻³`）。`release` も同様。

**物理単位の併記**: `p_M ≈ 5 kPa`、`c = 343 m/s` を仮定して γ → cmH2O、L → Hz を併記する。
これは**目安の換算であって較正された測定値ではない**。UI にもその旨を出す。

### 手順6 で確定する定数（暫定値）

以下は**発振閾値と跳躍閾値の実測（§10 手順6）に依存する**。暫定値のまま実装を始めてよいが、
手順6 で測定して確定させること。**測定前にこれらを「正しい」と扱わない。**

| 定数 | 暫定値 | 制約・根拠 |
|---|---|---|
| `γ_base_min` | **要測定**（暫定 0.40） | **実測した発振閾値 + マージン**。準静的理論値 1/3 = 0.3333 に損失分が上乗せされるので、暫定 0.30 では弱打鍵が無音になる |
| `γ_base_max` | 暫定 0.60 | 第1レジスタを維持できる上限。跳躍閾値未満 |
| `γ_ceiling` | 暫定 0.95 | **跳躍閾値より上**である必要がある。静的閉鎖 1.0 の手前。0.95 で跳躍領域に届くかは未確認 |

**順序不変条件**（手順6 の測定値がこれを満たす保証はない。満たすかを検証すること）:

```
γ_th_osc  <  γ_base_min  <  γ_base_max  <  γ_th_jump  <  γ_ceiling  ≤  0.95
（発振閾値・実測）                        （跳躍閾値・実測）
```

破れる例: 実測発振閾値が 0.55 でマージン 0.05 なら `γ_base_min = 0.60 = γ_base_max` で
**ベロシティのダイナミックレンジが消える**。閾値 0.58 なら `γ_base_min = 0.63 > γ_base_max` で
**範囲が反転**し、`γ_base = γ_base_min + velocity01·(γ_base_max − γ_base_min)` の傾きが負
（＝強く弾くほど弱くなる）。

**縮退方針**（測定値が不変条件を破った場合）:

1. `γ_base_max = γ_th_jump − マージン` を優先する（第1レジスタを維持できることが先）
2. それでも `γ_base_min ≥ γ_base_max` なら `γ_base_min = γ_th_osc + 小マージン` へ戻し、
   **ベロシティレンジが狭いことを受け入れる**
3. `γ_th_jump` が 0.95 に近ければ `γ_ceiling` を 0.95 未満へ下げず、
   代わりに `bellCutoff` の既定値を上げて `γ_th_jump` を下げる

不変条件は §9 テスト26 で assert する（定数は `src/params.js` から読む）。

**`γ_base_min` は既定パラメータでのみ校正される。** 発振閾値は
`zeta`（0.05 で結合が弱く閾値が大きく上がる）、`wallLoss`（0.90 は1往復 10 % 損失）、
`bellCutoff`（低いほど損失増）、`reedFreq` のいずれでも動く。
既定から離れたスライダー位置では `γ_base` が閾値を下回り**全打鍵が無音**になりうる。
これは**実物と同じ挙動として受容する**（損失を上げる／アンブシュアを締めると鳴らなくなる）。
「どの設定でも鳴る」ことは保証しない。手動受け入れ基準に
「`wallLoss` を下限にすると発音しなくなること」を積極的に載せる。

## 6. MIDI と演奏

### ノート → 管長

- ノート番号 → `f = 440·2^((n−69)/12)` → `L = c/(4f)`。
- クランプ `L ∈ [0.15, 1.2] m`（≒ **MIDI 38–74**。L=1.2 m → 71.5 Hz → MIDI 37.5、
  L=0.15 m → 572 Hz → MIDI 73.5）。範囲外のノートはクランプし、
  **実際に鳴っているピッチを上部バーに表示**（押鍵と発音がずれるため）。
- `tubeLength` AudioParam へは `setValueAtTime`。worklet 側の τ_D=15 ms グライド（§4.5）が
  遅延線の飛びを吸収する。
- **モノフォニック・後着優先**。押している鍵のスタックを持ち、離すと直前の音へ戻る（レガート）。

### ベロシティ・表現ソース → γ_target と gate

`velocity01 = velocity / 127`（線形、`velocity ≥ 1`）。**MIDI ベロシティ 0 のノートオンは
ノートオフとして扱う**（MIDI の慣例）。

`expr01` = 選択された表現ソースの現在値 [0..1]（`CC / 127`。どちらのコントローラも静止位置は 0）。

**ソースごとに写像が違う**（同一写像にすると3択が実質2種に退化し、ブレスの物理的意味が失われる）:

```
γ_base = γ_base_min + velocity01 · (γ_base_max − γ_base_min)

ブレス (CC2):
    γ_target = expr01 · γ_ceiling                        → [0, γ_ceiling]
    gate     = ノート在否のマスク（0/1、2 ms ランプ。attack/release は使わない）
    → 息のエンベロープがそのまま吹圧。息を止めれば音が止まり、γ_base より弱くも吹ける。
      §1 の「直流エネルギー源 = 吹圧」と物理的に整合し、立ち上がりの過渡（チフ音）が自然に出る

モジュレーション (CC1):
    γ_target = γ_base + expr01 · (γ_ceiling − γ_base)    → [γ_base, γ_ceiling]
    gate     = ノートオンで 0→1（τ=attack）、オフで 1→0（τ=release）
    → ホイール静止(0)で通常発音。上げると意図的に12度へ追い込める

なし:
    γ_target = γ_base                                     → [γ_base_min, γ_base_max]
    gate     = モジュレーションと同じ

実効吹圧 γ = gate · γ_target        ← worklet 内で積を取る（§5）
```

- どの経路も `γ_ceiling ≤ 0.95 < 1.0` を超えないので**クランプ不要**。
  R6 の原因（倍率の積み上げによる天井打ち）は再発しない。
- `gamma`（=γ_target）は `setTargetAtTime(γ_target, now, 0.02)` で書く。
  `gate` は `setTargetAtTime` を `τ = attack/3000` または `release/3000` で書く。
  **別々の AudioParam なので時定数が干渉しない。**
- ソース切替時は現在の `expr01` を保持して `γ_target` が飛ばないようにする。
- **ブレス選択時は `velocity01` を使わない**（`γ_base` を経由しない）。
  ブレスコントローラでは息が表現のすべてなので意図的。打鍵の強さは音量に影響しない。
- **時定数の役割分担**: 速い立ち上がりの過渡（チフ音）を作るのは `gate` の 2 ms ランプ。
  `gamma` の τ=20 ms は **CC の 128 段量子化を均すため**であって過渡を作る役ではない。
  20 ms のほうが遅いので、この分担を書かないと「息のエンベロープがそのまま吹圧」と矛盾して読める。
- CC2 は多くのブレスコントローラの既定。CC1 は全鍵盤にある。

> **改訂履歴**: 初版〜`6def6b2` の「倍率 1.0–1.5」方式は AudioParam 上限 1.0 で
> 天井打ちしたため改訂1で内分点写像へ変更（R6）。改訂1 は両ソースを同一写像にして
> しまったため（R26）、改訂2 でソース別写像へ戻し、
> ゲートと表現の時定数衝突（R25）を `gate` パラメータ分離で解いた。

### 裏返りインジケータ

上部バーに「管の f0（= c/4L）/ 実際に鳴っている f0 / 比」を出す。

- 実 f0 は `out[1]`（p̃）を `AnalyserNode.getFloatTimeDomainData` で取り、
  `src/pitch.js` の**自己相関**または**倍音列マッチング**（f0 候補に対し f, 3f, 5f の
  エネルギー総和を評価）で推定する。
- **スペクトルのピーク検出は使わない** — クラリネット波形は3次が基音より強いことが常で、
  第1レジスタでも「比 ≈ 3」と誤判定する。bin 分解能（fftSize 2048 @48 kHz で 23 Hz）も
  低音（71 Hz）に対して粗い。
- **自己相関の前に窓内平均を引く**（または1次ハイパスを掛ける）。`p̃` は
  γ に依存した正の DC オフセットを持ち、除かないと相関関数が DC 項に支配されて
  ラグに対しほぼ平坦になり、ピーク検出が不安定になる。
  `out[0]` は `(1+R)` と DC ブロッカで DC が除かれているが、
  **インジケータの入力は `out[1]` なのでその恩恵を受けない。**
  倍音列マッチングを使う場合も 0 Hz bin を除外する。
- **`fftSize ≥ 2048` が要件**。自己相関で最長管の 71.5 Hz（周期 672 サンプル @48 kHz）を
  取るには最低 2 周期 = 1343 サンプル要る。§9 テスト27 も同じ窓長で走らせる。
- 比 ≈ 1 なら第1レジスタ、≈ 3 なら第2レジスタ。

### フォールバック

Web MIDI 非対応/拒否 → QWERTY 鍵盤（`z s x d c…` の半音配列）+ 画面に表示。

| パネル | 中身 | データ源 |
|---|---|---|
| 1. リード相図 | `(x, x')` の軌跡をフェード付きで。**x=0 線**（ビーティング境界）を引く。リミットサイクル、**x<0 側へ減衰しながら潜る閉鎖区間**、裏返り時の軌道変化が見える | snapshot（`x`, `xd`） |
| 2. 非線形特性 + 動作点 | 準静的特性曲線 `ũ(Δp̃)`（**準静的近似 `x = 1 − Δp̃` を代入した `ũ = ζ·max(1−Δp̃, 0)·sign(Δp̃)·√|Δp̃|`**）と、その上を回る動作点の軌跡（直近 ~21 ms、低音では2周期未満のこともある） | snapshot（`dp`, `u`） |
| 3. 管内の定在波 | `p⁺(z)`, `p⁻(z)`, 和 を管軸に沿って。左=リード端(`z=0`)、右=ベル(`z=nTube`)。**節・腹の数が 1→3 に変わる瞬間**が見える | snapshot（`pPlus`, `pMinus`, `nTube`） |
| 4. スペクトル / 時系列 | `p̃` の波形（~40 ms）とスペクトル。奇数倍音列と、基音が3倍へ飛ぶのが周波数軸で見える | **`AnalyserNode`（out[1]）** — FFT・時間波形とも main 側、audio thread に乗らない |

> パネル1に**平坦部は出ない**。§4.1 は接触時に減衰を増やすだけで `x` をクランプしないので、
> 閉鎖中も `x` は 0 以下へ動き続ける。平坦部が見えるのはハードクランプか接触剛性を
> 入れたモデル（非目標）。

> **パネル3 は `pMinus` を反転して同じ `z` 軸へ写す。** 2本の遅延線は
> インデックスの向きが逆（`pPlus` は先頭がリード端寄り、`pMinus` は先頭がベル端寄り）。
> 反転せずに `pPlus[i] + pMinus[i]` を「和」として描くと**節・腹の位置が物理と一致しない**。
> `z=0` をリード端、`z=nTube` をベル端に固定し、和は `pPlus[i] + pMinus[nTube−1−i]` で取る。
> 中心要件3 と、要件1 の検証手段（「節・腹の数が 1→3 に変わる」）が静かに壊れる箇所。

**snapshot の中身**（`port.postMessage`、約 30 Hz、Float32、約 18 KB）:

| フィールド | 長さ | 内容 |
|---|---|---|
| `fsInternal` | 1 | 現在の内部レート（時間軸換算用） |
| `cpu` | 1 | CPU 負荷の指数移動平均 |
| `nTube` | 1 | `pPlus`/`pMinus` の有効長 = `min(floor(D_eff), 256)`。`D_eff` はグライド中に小数を取るので **floor** で丸める（`pPlus[nTube−1]` まで有効） |
| `x`, `xd` | 各 1024 | リード開口と速度。連続 1024 サンプル（送出間隔 33 ms のうち 21 ms 分。相図・特性図には非連続でも無害） |
| `dp`, `u` | 各 1024 | Δp̃ と ũ |
| `pPlus`, `pMinus` | **各 256 固定** | 遅延線の中身。先頭 `nTube` 要素のみ有効。パネル3側でキャンバス幅へ線形リサンプル |

描画は 30 fps、キャンバスは 380×260 CSS px、`devicePixelRatio` は 2 で上限。

- `AudioWorklet` 非対応 → メッセージ表示して停止
- Web MIDI 非対応/拒否 → QWERTY フォールバック
- **数値発散ガード**: `process()` の**ブロック末に1回**、`!isFinite(p̃) || |p̃| > 1e3` を検査。
  引っかかったらリード状態 `(s1,s2)` と遅延線と FIR 状態を全ゼロにし、
  `port` で `diverged` を通知、`out[0]` を無音から 5 ms でフェードイン。
  `wallLoss = 1.0` + γ 大 のような範囲の端で起こりうる。
- **出力段のサンプル毎ガード**: ブロック末の検査だけでは最大 128 サンプルの NaN/Inf が
  出力へ抜ける（`tanh(NaN) = NaN`）。§4.4 手順9 の最後で
  **`out[0]` と `out[1]` の両方にサンプル毎の非有限→0 ガードを掛ける**。1サンプル1比較なので安い。
  `out[1]` を素通しにすると `AnalyserNode.getFloatTimeDomainData` が `NaN` を返し、
  **自己相関が `NaN` になって裏返りインジケータが壊れる**。
  `fftSize = 2048`（42.7 ms）の窓なので、1回の発散で 43 ms 分の表示が汚染される。
  `out[1]` は `destination` に繋がないのでスピーカーの危険はないが、UI の復帰が
  `diverged` 通知だけに依存してしまう。
- 最終段に `tanh` ソフトリミッタ（スピーカー保護）。

### 自動テスト

**閉形式ソルバ（§4.3）— 唯一の非自明な代数**

1. 閉形式解が §4.2 の非線形式を満たす（残差 < 1e-10）— γ, ζ, X, p⁻ の格子で総当たり
2. `ũ` の符号が `Δp̃` の符号と一致
3. `X = 0`（ビーティング中）で `ũ = 0`
4. **`b = 0` 近傍の分岐連続性** — `b` を `−ε … +ε` で掃引し `ũ(b)` が連続かつ単調。
   2分岐の継ぎ目（不等号の向き、片側の符号）の実装ミスを捕まえる

**自励振動の素性**

5. `γ = 0` で発振しない（静止へ減衰）。数値エネルギー注入で「鳴ってしまう」モデルを弾く
6. 発振閾値が存在する — γ を掃引して無振動→振動の境界が `0.2 < γ < 0.6` に1つある
   （準静的理論値は 1/3 だが動特性と損失でずれる。値は決め打ちしない）。
   **測定した閾値を手順6 で `γ_base_min` の確定に使う**（§5）
7. **既定パラメータで** 定常 f0 が `fsInternal/(4·D_eff)` の ±5 % 以内、かつ L に対して単調。
   **測定前に `3·τ_D = 45 ms` のグライド静定を待つ**（§4.5 のグライドがあるため）。
   テスト12・13 の掃引でも各点で同じ待ちを入れる
   （端の `bellCutoff = 200 Hz` では −19 % になるので既定パラメータ限定）
   > **実装ノート（手順1 で判明）**: 既定パラメータ（`bellCutoff=1500Hz`, `reedFreq=2200Hz`）
   > でも、リード（TPT）とベル反射フィルタの群遅延は発振周期に対しほぼ**一定サンプル数**
   > （実測 ~10.5 サンプル）で乗る。周期が短いほど相対誤差が拡大するため、
   > `L=0.15 m`（MIDI 上限付近）では ±5 % を満たさず実測 ~12.6 %、`L=0.3 m` で ~6.3 %。
   > `L ≥ 0.6 m` では 5 % 以内（実測 3.2/2.1/1.6 %）。単調性は全域で成立する。
   > これはリード共振（2200 Hz）とベル反射（1500 Hz）がどちらも発振周波数域
   > （71–572 Hz）より十分高くても位相寄与がゼロにならない、通常の管楽器モデルに
   > 共通する性質（実物のクラリネットも高音域でリードのコンプライアンス分だけ
   > ピッチが理論値からずれる）。**バグではない。** テスト7 は `L=0.15 m` を
   > ±5 % 判定から除外し、`L=0.3 m` は許容を 7 % に緩めて実装している
   > （[`tests/model.test.js`](../../../tests/model.test.js) test7）。単調性チェックは全域で行う。

**リードと導波路の構造**

8. **係数切替（開放↔接触）の連続性** — TPT を採用した唯一の根拠。
   同一サンプルで `k` を切り替えても状態 `(s1, s2)` が変化しないこと（構造上の不変量）を
   直接 assert。加えて `x` が 0 を跨ぐ区間で、切替前後1サンプルの `(x, x')` の差が
   連続 ODE から予測される変化量の許容倍率内であること
9. **ループ全遅延 = `2·D_eff`** — `X = 0` を強制して完全反射にし、リード端にインパルスを
   入れて戻るまでのサンプル数が厳密に `2·D_eff`（整数 `D` を `delaySamples` で直接指定）。
   テスト7 の ±5 % では隠れる off-by-one を確実に捕まえる（§4.5 の規約の検証）
10. 遅延線の線形補間が整数 `D`（`delaySamples` 直接指定）で厳密一致
11. **共鳴器の受動性** — `X = 0` を強制（リードを閉じたまま＝完全反射終端）してインパルスを入れ、
    遅延線の**エネルギー** `Σ(p⁺² + p⁻²)` を**1往復 `2·D_eff` サンプルごと**に評価し、
    **1往復あたりのエネルギー比が `wallLoss²` 以下**
    （エネルギーは振幅の2乗。上界を `wallLoss` にすると `wallLoss=0.995` で
    0.990–0.995 の利得を見逃す）。
    （`γ=0` でも `x→1` でリード端は非線形抵抗性終端になるので「共鳴器単体」にならない。
    またエネルギーは波の移動でサンプル毎に揺れるのでサンプル毎の単調減少は成立しない）

**中心要件（探索的。閾値の確定は §10 手順6 の後）**

12. パラメータ空間に **1次→3次の跳躍が存在する** — γ を上げる、または `bellCutoff` を
    上げる掃引で、実 f0 / (c/4L) の比が 1 近傍から 3 近傍（2.5–3.5）へ不連続に飛ぶ点がある。
    γ 単独で出なければ (γ, bellCutoff) の2次元掃引で探す。
    **測定した跳躍閾値を手順6 で `γ_ceiling` の確定に使う**
13. `reedFreq` を下限へ動かすと、発音周波数が管モード（c/4L の奇数倍）から外れ
    `reedFreq` 近傍へ寄る点がある（スクイーク）

**数値健全性**

14. パラメータ全範囲の端の組合せ（2次元グリッド）で 5 秒回して NaN/Inf が出ない
15. **ブロック境界不変性** — 同じ入力を 1 回の `process(N)` と N/128 回の `process(128)` で
    処理し、出力が一致（状態管理・ブロック継ぎ目のバグを検出）
16. **決定性** — 同じシード・同じ入力で 2 回走らせて出力ビット一致
17. **a-rate パラメータ配列の扱い** — 定数 `v` に対し
    `process(blockLen, { gamma: new Float32Array([v]) })` と
    `process(blockLen, { gamma: Float32Array.from({length: blockLen}, () => v) })` の
    **出力がビット一致すること**。
    「長さ1配列を先頭要素としてしか読まない」「毎サンプル `arr[i]` を読んで
    範囲外アクセスする」の両方を捕まえる。AudioWorklet が k-rate 時に長さ 1 の配列を
    渡す実仕様と同じ2形態をヘッドレスで検証する
18. **長時間振幅安定性** — 既定パラメータで 20 秒、定常後の RMS が最初の1秒と ±10 % 以内
19. **出力 DC の絶対量** — 既定パラメータで定常後 5 秒の `out[0]` の平均が振幅 RMS の 1 % 未満。
    `(1+R)` と DC ブロッカが効いているかの直接確認
20. **発散ガードの復帰** — 内部状態に人為的に `Infinity` を注入し、次の `process()` で
    リセットが働き、以降の出力が有限かつ 5 ms でフェードインすること。
    §8 の復帰経路が一度も実行されないまま出荷されるのを防ぐ

**オーバーサンプリングと補間**

21. **2× 実装の正しさ** — **2× と 4×（テスト専用の参照レート）**で定常 f0 が ±1 %、
    第1–5倍音の相対レベルが ±3 dB。
    （1× と 2× を比較してはいけない。**両者が違うことがオーバーサンプリングを入れる理由**なので、
    一致を要求すると 2× が不要か、正しい実装でも落ちるかのどちらかになる）
22. **1× vs 2×** は f0 が ±1 % と総 RMS が ±10 % のみを見る
23. **ハーフバンド FIR 係数** — 係数配列の対称性、DC 利得 = 1、`fsInternal/4` で −6 dB、
    阻止域減衰が目標値以上
24. **パラメータランプの滑らかさ** — `tubeLength` を 50 ms かけて端から端へ動かし、
    `out[0]` の隣接サンプル差が**掃引終端の L で測った静定時の最大値**の 3 倍を超えない。
    （基準を掃引開始側 L=1.2 m/71 Hz で取ると、終端 L=0.15 m/572 Hz では
    **周波数比 8.0 倍だけで 3 倍の閾値を超え**、正しい実装でも落ちる）

**制御層の純関数（`src/midi.js`, `src/pitch.js`）**

25. `noteToLength(note)` — MIDI 38/74 のクランプ境界、37/75 でクランプが効くこと、
    `L = c/(4f)` の値の正しさ
26. `computeGammaTarget(velocity01, expr01, source)` —
    **γ 定数は `src/params.js` から読む**（テスト側にハードコードしない。手順6 で値が変わるため）。
    **順序不変条件 `γ_base_min < γ_base_max < γ_ceiling ≤ 0.95` を assert**（§5、R48）。
    不変条件 `γ_target ≤ γ_ceiling < 1.0`、
    ソース別写像（ブレスは `expr01=0 → 0`、モジュレーション/なしは `expr01=0 → γ_base`）、
    `expr01` に対する単調性、`velocity=0` がノートオフ扱いになること
27. `estimateF0(buf, fs)` — 合成波形で検証:
    - `f + 3f + 5f`（**3f を基音より 6 dB 大きく**）+ DC オフセット → `f` を返すこと
      （R2 の失敗モードそのもの。DC 除去（§6）が効いているかも同時に見る）
    - `f = 71 Hz`（最長管）と `572 Hz`（最短管）の両端
    - 第2レジスタ相当（`3f` 主体）で `3f` を返すこと
    - 比の判定が 1 近傍 / 3 近傍で正しく分かれること

**改訂2・3 で新設した仕組みの検証**

28. **`gate × gamma` の積** — `(gate, gamma) = (1.0, 0.5)` / `(0.5, 1.0)` / `(0.7071, 0.7071)` で
    出力が一致すること（積 = 0.5 が同じ）。併せて `gate = 0` で常に無音。
    片方だけ読む・加算になっている等の分離ミスを捕まえる（§5, §6 の2本分離）
29. **`D_eff` グライドの `|dD/dt| < 1` 制約** — `τ_D` をコンストラクタ引数にし、
    `τ_D = 15 ms` で最大跳躍 `ΔD = 147` を与えたとき全サンプルで
    `|D_eff[n] − D_eff[n−1]| < 1`。併せて `τ_D = 2 ms` では成立しないこと
    （＝制約が実在すること。定数を後から縮めたときに気付ける）
30. **2× 切替後のループ遅延** — 1× で定常発振させ `setOversample(2)` 相当を呼び、
    フェード明け + グライド静定後の f0 が切替前と ±1 % 以内。
    `D_eff` をグライドさせる実装（R52 のバグ）なら切替直後に 1 オクターブずれて落ちる。
    テスト9 は 1× のみを見るのでここでしか捕まらない
31. **非有限ガードが同じブロック内で効く** — 内部状態に `Infinity` を注入した
    **そのブロックの 128 サンプル全部**が `out[0]` `out[1]` とも有限であること。
    テスト20 は「以降」しか見ないので、§8 のサンプル毎ガードを外しても通ってしまう
32. **パネル3 の `z` 軸整列** — `pPlus` と `reverse(pMinus)` の和を取る写像を
    純関数として切り出し、既知の f0 に対し `nTube` 区間の節が
    `(2k+1)/4` 波長の位置に来ること。R53（`p⁻` の反転漏れ）は目視では気付きにくく、
    中心要件3 が静かに壊れるので数値で押さえる

### 手動受け入れ基準

- MIDI 鍵盤で発音、レイテンシが許容範囲
- 吹圧を**ゆっくり**上げる → 閾値で鳴り始め、さらに上げると12度上へ裏返る
- ブレスコントローラで息を止めると音が止まる（ブレス選択時）
- `wallLoss` を下限（0.90）にすると発音しなくなる — 実物と同じ挙動として**期待される結果**
  （`γ_base_min` は既定パラメータでのみ校正されている。§5）
- `reedFreq` を下げるとスクイーク
- レガートで音がクリックなく繋がる
- 通常演奏で不要なスクイーク・ワーブルが出ない
- 4パネルが 30 fps 前後で破綻なく更新
- CPU 実測 → `oversample` の既定値を決定
